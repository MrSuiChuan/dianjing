# dianjing · 画龙点睛

一句话选题 → 10 条能直接用的文章标题(公众号 / 知乎 / 小红书 / B 站)。每条标清**传播机制**、公式类型和钩子解读,交付前还要过一遍标题查重。

> 配套 skill:[hualong](https://github.com/MrSuiChuan/hualong) 写正文。hualong 画龙,dianjing 点睛,合起来是一句"画龙点睛"。

## 它凭什么不一样

**1. 规则是量出来的,不是拍脑袋的。**
提炼自 610 条真实标题 + 442 篇带赞数样本的逆向分析,不是"我感觉这样写会火"。

**2. 它敢说哪些规则没用。**
实测下来,标题的字数(与点赞的相关性 0.046)、有没有数字(0.025)、用不用问号,和最终点赞**几乎没有关系**。所以这些只用来适配平台显示,不拿来预测效果。这个 skill 不承诺流量。

**3. 唯一有证据的偏好:立场。**
批判、冲突类结构在头部样本里占 13.8%,在全量里只占 1.5%——高下立判。所以每批 10 条里,至少 2 条必须带明确立场,而不是中性描述。

**4. 交付前过机器检查,不靠手感。**
`scripts/title_overlap_check.py` 拿候选标题和 610 条索引做连续比对,**重合 ≥10 字判不合格**——标题短,撞车比长文更常见也更难解释。

**5. 用完能自己校准。**
`scripts/title_feedback.py` 用来回填发布后的曝光、点击、点赞,攒够数据就能按你自己账号的基线排序,而不是一直借用别人的。

**6. 标题不能空口承诺。**
和 [hualong](https://github.com/MrSuiChuan/hualong) 共用一份交接契约:正文定稿后产出 `title-brief`,标题里的每个数字都要能在正文找到。交付前用 `scripts/promise_check.py` 逐条核验 Top3——标题数字必须 100% 兑现,关键词覆盖率低于 45% 判不合格。

## 产出长什么样

| # | 标题 | 传播机制 | 公式类型 | 钩子解读 |
| --- | --- | --- | --- | --- |
| 1 | 我把三台旧手机改成了本地推理集群 | 信息差 | ①玩梗体验 | 低成本 + 自造 |
| 2 | 别再手改配置了,这三个开关能省你半小时 | 利益 | ③工具实操 | 直接省时间 |
| 3 | 把提示词写得又长又全,正在毁掉你的判断力 | 立场 | ⑥批判冲突金句 | 站队 + 危机感 |

这三条都过了查重(最长重合 2–4 字),可以直接照着这个结构换选题。

配额是硬性的:**5 种传播机制各 2 条**——信息差(你不知道但我查到了)、身份共鸣(说的就是我)、利益(能省什么 / 赚什么)、情绪(愤怒、惋惜、兴奋)、立场(我认为这是对的或错的)。

公式类别不强制配比:6 类公式只覆盖 38% 的语料,硬凑每类一条,凑出来的往往正是最平庸的那几条。

## 6 类公式速览

| 类型 | 一句话 |
| --- | --- |
| ① 玩梗 / 体验揭秘 | 我用 X 做了一件 Y,结果 Z |
| ② 测评 / 首发 | 一手实测,给出定调式判断 |
| ③ 工具实操 | 降低门槛,带具体步骤和产物 |
| ④ 开源 / 分享 | 代价前置 + 我开源了 X |
| ⑤ 思考 / 心得 | 反常识真相,或者经验分级 |
| ⑥ 批判 / 冲突 / 金句 | 把矛头指向具体对象,敢下判断(头部样本里占比最高) |

完整公式、49 条真实样本和生成 Prompt 见 `references/title_formulas.md`。

## 安装

```bash
git clone https://github.com/MrSuiChuan/dianjing.git ~/.codex/skills/dianjing
```

Windows 是 `%USERPROFILE%\.codex\skills\dianjing\`,也可以直接拷目录。

## 用法

```
用 $dianjing 帮我想 10 个标题。选题是…… 平台:公众号;读者:1-3 年 AI 从业者
```

一句话选题就能跑。建议补上垂类、平台和读者,标题会更贴场景。

想换一批:说"换一批";只想要某一类:说"只要批判冲突那一类,多给我几条"。

## 发布后回填(可选,但强烈建议)

```bash
py -3 scripts/title_feedback.py --add --title "标题原文" --platform 公众号 \
    --category "⑥批判冲突金句" --mechanism 立场 \
    --impressions 12000 --clicks 900 --likes 120

py -3 scripts/title_feedback.py --report   # 按类别/机制/平台复盘
```

攒够 10 条以上,你就有自己账号的标题基线了。

## 和 hualong 怎么配合

| 场景 | 路径 |
| --- | --- |
| 只出标题 | 有正文:dianjing → 逐条承诺检测;没正文:先定选题角度 |
| 只写正文 | [hualong](https://github.com/MrSuiChuan/hualong) → 交付正文 + `title-brief` |
| 完整链路 | hualong 写正文 → title-brief → dianjing 出 10 条 → promise_check 核验 Top3 → 发布 |

契约细节(交接字段、验收线、标题先行的回环规则)全在 `references/handoff.md`。它解决的是实测里唯一有正向信号的环节:**标题和正文的一致性**(关键词覆盖率与点赞相关性 0.183,高于标题词法的 0.09 和正文风格的 0.14)。

## 数据与局限

| 数据 | 规模 | 用途 |
| --- | --- | --- |
| 标题索引 | 610 条(去重) | 公式提炼、真实措辞参考、查重底库 |
| 赞数样本 | 442 篇(带发布时间) | 特征与点赞的相关性分析 |

局限也写在这里:赞数样本只覆盖 71%,相关性分析做了"同一年内排名"控制,但仍然是单账号、单平台(知乎)、词法特征。公众号和小红书的基线还没验证;账号权重、话题热度、发布时间的影响,标题层面解释不了。

**结论分三档**:能当规则的只有"立场和冲突结构更多出现在头部""必须具体""不许撞车";字数、数字、问号属于无证据项;跨平台和跨垂类属于未验证项。
