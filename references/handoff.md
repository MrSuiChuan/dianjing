# 交接契约:hualong ↔ dianjing

正文和标题之间只通过这份契约交接,不靠口头摘要。

## 一、交接物:title-brief

正文定稿后,由 hualong 产出下面这个块(字段固定,没有内容的写"无",但不许缺字段):

```markdown
## title-brief
- 选题:一句话
- 平台:公众号 / 知乎 / 小红书 / B站
- 读者:…
- 正文模式:技术文 / 人文文
- 目标字数 / 实际字数:2800 / 2874
- 人味分:92(style_check 的结果)
- 钩子:3 条,每条写清它在正文哪一段被支撑
- 可核查数字:数字 + 在正文的位置(没有就写"无")
- 核心立场:一句判断
- 不能碰的表述:正文没写、标题不许出现的说法
```

dianjing 拿到这个块之后**不必通读全文**,但必须用 `promise_check.py` 核验一遍。

## 二、验收线(语料实测)

| 项 | 线 | 依据 |
| --- | --- | --- |
| 标题里的数字必须出现在正文 | 100% | 含数字的 287 篇里,兑现率中位 1.0、均值 0.958 |
| 标题关键词全文覆盖率 | ≥0.65 理想,≥0.45 底线 | 语料中位 0.647、p10 0.444 |
| 正文前 1/4 的覆盖率 | **不作要求** | 与点赞相关性 0.116,低于全文的 0.183 |

最后一条是刻意的:数据不支持"钩子必须开头就兑现"。硬要求开头兑现,会逼出摘要式的开头,反而毁掉正文节奏。

## 三、三种链路

| 场景 | 路径 |
| --- | --- |
| 只写正文 | hualong → 交付正文 + title-brief |
| 只出标题 | 有正文:dianjing → 逐条 promise_check;没正文:先定选题角度,再补一份最小 title-brief |
| 完整链路 | hualong(正文)→ title-brief → dianjing(10 条)→ promise_check 核验 Top3 → 发布 |

## 四、标题先行(允许,但必须回环)

投稿、选题会这类场景需要先有标题时:

1. 先出标题草稿;
2. 用标题里的钩子反推正文骨架——标题承诺什么,正文就得写什么;
3. 正文写完跑 `promise_check` 回环校验;
4. 不达标就二选一:改标题,或补正文,**不许两边都不动**。

## 五、责任边界

- **hualong 对"正文兑现了什么"负责**:title-brief 里的每个数字都要能在正文查到,钩子要指得出段落。
- **dianjing 对"标题不越界"负责**:正文没写的对象、数字、判断,不许出现在标题里。
- **发布后一起回填**:用 `title_feedback.py` 记录时,把正文模式和人味分一并写进去,复盘才能算"传播机制 × 正文模式"的组合效果。

## 六、这份契约的边界

实测口径:441 篇带赞数样本、单账号单平台;"标题关键词覆盖率"用字符二元组计算,是粗代理。所以阈值是起点,不是定律——攒够自己的反馈数据后按 `title_feedback.py --report` 调。
